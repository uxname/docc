# update: отличия Rust от Go

### 1. Пояснение к коду ответа сервера
Было: Go печатал пояснение к коду так, как его прислал сервер. Зеркало на `python3 -m http.server` отвечает «404 File not found», и Go писал `docc: error: download failed: <адрес>: 404 File not found`.
Стало: Rust пишет стандартное пояснение к коду: `<адрес>: 404 Not Found`. Для кода, у которого нет стандартного пояснения (например 599), — `599 <unknown status code>`.
Почему: сетевая библиотека Rust (ureq) не сохраняет пояснение сервера. GitHub и обычные веб-серверы (nginx и другие) присылают стандартное пояснение, поэтому с ними текст одинаковый.

### 2. Текст ошибки у повреждённого содержимого архива
Было: если архив выпуска повреждён внутри, но его контрольная сумма совпадает с checksums.txt, Go писал текст своей библиотеки распаковки, например `docc: error: unexpected EOF` у обрезанного архива.
Стало: Rust пишет текст своей библиотеки: `docc: error: incomplete deflate stream`. Код выхода 2 и то, что программа не заменяется, остались прежними. Испорченный заголовок архива (`gzip: invalid header`, `zip: not a valid zip file`) и архив без docc внутри (`... has no docc binary`) дают те же тексты, что в Go.
Почему: такой архив может появиться, только если выпуск опубликован уже испорченным вместе с его контрольной суммой; повторять внутренние тексты чужой библиотеки распаковки ради этого случая не стоит.

### 3. Проверка сертификата сайта на macOS и Windows
Было: на macOS и Windows Go проверял сертификат сайта выпусков средствами самой системы: доверял всем корневым сертификатам, установленным в системе, в том числе сертификату корпоративного прокси, который подменяет HTTPS.
Стало: на macOS и Windows Rust доверяет встроенному списку корневых сертификатов (список Mozilla, тот же, что в Firefox). С github.com всё работает так же, но в корпоративной сети, где HTTPS подменяется своим сертификатом, `docc update` выдаст ошибку сертификата. Обход: указать файл с нужными сертификатами в переменной `SSL_CERT_FILE` (или папку в `SSL_CERT_DIR`) — тогда Rust, как и Go, берёт сертификаты оттуда. На Linux Rust, как и Go, читает системные сертификаты из `/etc/ssl/certs` и соседних мест, и эти переменные тоже работают.
Почему: для проверки средствами macOS и Windows нужна ещё одна библиотека, а добавлять библиотеки при переносе нельзя.
