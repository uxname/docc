# config: отличия Rust от Go

### 1. Другое пояснение к части ошибок в регулярном выражении своего правила
Было: если в `customRules` в `forbid` или `require` записать неправильное выражение, например `(`, Go писал `docc.json:1:85: config error: bad regular expression: error parsing regexp: missing closing ): ` + "`(`".
Стало: Rust пишет то же место в файле и то же начало `bad regular expression:`, но причину своими словами: `bad regular expression: unclosed group`. Для записей, которые Rust сам по себе принял бы, а Go отвергает (`A`, `[[:foo:]]`, `(?P<a.b>x)` и подобные), Rust пишет ровно тот же текст, что Go.
Почему: причину большинства ошибок формулирует библиотека регулярных выражений, а в Rust она другая. Место ошибки и сам факт ошибки совпадают.

### 2. Несколько редких записей в регулярных выражениях теперь принимаются
Было: Go отвергал как ошибку записи `(?x)` и `(?u)`, повтор больше 1000 раз (`a{1001}`), повтор повтора (`a**`, `a{2}{3}`) и названия групп символов, которых он не знает: `\p{IsLatin}`, `\p{Alphabetic}`, `\p{scx=Greek}`.
Стало: Rust принимает их и проверяет текст по такому выражению. Все обычные записи (`\w`, `\d`, `\s`, `\b`, `[...]`, `[a-z0-9--]`, `{2,3}`, `\Q...\E`, `(?i)`, `\p{L}`, `\p{Greek}`, `\p{^L}` и другие) работают как в Go.
Почему: так устроена библиотека регулярных выражений Rust, а повторить в точности список названий Go значит переписать его таблицы; в правилах документации такие записи не встречаются.

### 3. Символ-«половинка» `\x{D800}`…`\x{DFFF}` в выражении — ошибка
Было: Go принимал выражение вроде `\x{D800}` и просто никогда ничего им не находил.
Стало: Rust сообщает об ошибке в выражении: `bad regular expression: hexadecimal literal is not a Unicode scalar value`.
Почему: такие коды не бывают в настоящем тексте, а библиотека Rust не позволяет их записать. Правило, которое ничего не может найти, всё равно бесполезно.
